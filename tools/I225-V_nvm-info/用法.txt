nvm_info.exe —— Intel I225 / I226 (Foxville) 固件镜像离线查看工具
================================================================
版本：1.0 (rust)      编译日期：2026-09-28      用途：倍控 G31-1338 四口机 I225-V 固件升级


【这是什么】
    一个零依赖的单文件命令行小工具，不用上机、不用装 eeupdate，
    直接在 PC 上读出任意 .bin 固件镜像的关键字段 —— 尤其是 **EtrackID (EEPID)**。

    约 900 KB 的单文件 exe，拷到任何 Windows 机器上就能用，
    不需要 Python、不需要 .NET、不需要任何运行库。


【最省事的用法】
    把一个（或按住 Ctrl 选多个）.bin 文件，直接拖到 nvm_info.exe 图标上松手，
    会弹出黑窗口显示结果，看完按任意键关闭。
    也可以用 nvm_info.bat（同样的拖法，它会优先调 exe，没有才退回 Python 版）。


【命令行用法】
    nvm_info.exe 镜像.bin                       查看单个镜像
    nvm_info.exe 备份.bin 升级镜像.bin           多个镜像，自动出对照表
    nvm_info.exe 目录 [-r]                      扫描目录，-r 为递归
    nvm_info.exe 官方包.zip                     不解压，直接读 zip 里的镜像
    nvm_info.exe 官方包.tar.gz / .tgz           不解压，直接读 tar.gz 里的镜像
    nvm_info.exe --list-known                   打印已记录的 EEPID 对照表
    nvm_info.exe --json 镜像.bin                机器可读输出（JSON）
    nvm_info.exe --help                         帮助

    多个参数可以混着给，例如：
        nvm_info.exe 备份目录 某个.zip 单独一个.bin


【它会输出什么】

    文件名 / 来源路径 / 大小 / MD5

    MAC 地址        @0x00
    闪存容量索引    @0x07     0x0D = 1MB 结构；0x05 = 2MB 结构
    NVM 版本        @0x0A     0x1094 -> 1.94；0x1057 -> 1.57；0x1089 -> 1.89
    Vendor ID       @0x18     一般是 0x8086
    Device ID       @0x1A     15F3=I225-V，15F2=I225-LM，125C=I226-V，125D=I226-LM
    Subsystem ID    @0x1C     通常是 8086:8200
    镜像类型        @0x20     0x8022 = 1MB；0x80A2 = 2MB（与 0x07 互证）
    EEPID / Etrack  @0x84     <- 通常就是为了看这个

    另外会自动体检，有问题在最后用 [!] 列出：
    - 0x07 与 0x20 指向的容量不一致 → 头部可能损坏
    - Vendor 不是 0x8086 → 可能不是 Intel NVM 镜像
    - DeviceID 不在 Foxville 已知表里 → 型号对不上
    - 2MB 文件：自动比对前后两半是否完全相同
        完全相同 → 这是同一份 1MB 镜像被 dump 了两遍，刷机要选 1MB 镜像
        不同     → 确实是真实的 2MB 结构

    给两个及以上文件时，末尾出一张「汇总对照」表，一致/不同一目了然；
    正好两个文件时，额外给出字段级差异摘要（含整片不同字节数）。


【★ 针对本机的 1MB / 2MB 这个坑】
    本机四个口共用一片闪存，`eeupdate /dump` 出来的备份是 2,097,152 字节，
    但它 **前后两半逐字节完全相同**，本质是一份 1MB 结构的 NVM 被输出了两遍。
    所以本机必须用 **1MB 镜像**刷（Foxpond1_I225_15F3_V_1MB_1p94.bin 是对的）。
    工具会自动给出这个判断，不用自己数字节。


【0x84 到底是依据什么定的】
    不是猜的，是用 Intel 一手包标定的：

      Intel 官方驱动包 Release_31.2.2
      └─ NVMUpdatePackage\I225\I225_NVMUpdatePackage_v1_00_Linux\Linux_x64\

      该目录下两个镜像的**文件名自带 EEPID 后缀**，实测 u32@0x84 一比一命中：
        FoxPond1_I225_15F2_2MB_1p94_800003BB.bin      -> @0x84 = 0x800003BB  [OK]
        Foxpond1_I225_15F2_LM_1MB_1p94_800003BC.bin   -> @0x84 = 0x800003BC  [OK]
      同目录 nvmupdate.cfg 里写的 "EEPID: 800003BB / 800003BC" 也是同一批值
      → 文件名、cfg、镜像头三方互证。

    想自己验证（不用解压）：
        nvm_info.exe Release_31.2.2\NVMUpdatePackage\I225\I225_NVMUpdatePackage_v1_00_EFI.zip


【本机已实测到的 EEPID】

    0x800003FC   Foxpond1_I225_15F3_V_1MB_1p94    15F3 / 1MB / NVM 1.94   <- 待刷的升级镜像
    0x80000182   60BEB402680E.bin（本机备份）     15F3 / 1MB / NVM 1.57   <- 出厂老固件
    0x800002FC   FXVL_15F3_V_1MB_1.89             15F3 / 1MB / NVM 1.89   Vendor 0x17AA
    0x800002F4   FXVL_15F3_V_2MB_1.89             15F3 / 2MB / NVM 1.89
    0x800003BB   Intel 官方 15F2 2MB 1.94
    0x800003BC   Intel 官方 15F2-LM 1MB 1.94

    注意：同一个芯片型号，1MB 和 2MB 的 EEPID 是不一样的（1.89 那两个就是例子），
    选型不能只看型号和版本号，必须 EEPID + 0x07/0x20 一起确认。


【源码与重新编译】

    nvm_info.rs      源码，单个文件，**零第三方依赖，只用 Rust 标准库**
                     （MD5、DEFLATE/inflate、gzip、zip、tar 全是手写实现）
    nvm_info.exe     编译产物（x86_64 Windows）

    重新编译：装好 Rust（https://rustup.rs）后一条命令即可

        rustc -O -C opt-level=s -C panic=abort -C strip=symbols -o nvm_info.exe nvm_info.rs

    想维护已知值/备注：改 nvm_info.rs 里的 known_eepid() 再重新编译即可。
    同理 devid_label() / flash_idx_label() / nvm_version_label()
    分别管型号名、容量索引、版本解码。


【同目录另外几个文件】
    nvm_info.py      同功能的 Python 实现（功能等价、输出一致，可交叉核对）
    nvm_info.bat     Windows 拖拽启动器，优先调用 exe，没有才退回 Python 版
    平时只用 nvm_info.exe 就够了，其余是为了留底和核对。
